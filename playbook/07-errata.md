# 07 v1 勘误

> 归属：AI Coding Agent 软件工程手册
> 仅在需要了解旧规则为何失效时阅读；日常编码不需要。

v1（最后修改 2026-05-24）的问题与处理。保留此表是为了让后续 Agent 知道哪些旧规则不再有效。

| # | v1 问题 | 处理 |
| --- | --- | --- |
| 1 | 使用 Unicode 制表符 140 处（U+2500 系列 4 个字符），违反 CLAUDE.md 的 ASCII 输出约束 | 全部改为 ASCII |
| 2 | 文件行数阈值三处不一致：Rule 1（500）、Rule 9（controller 300 / service 400 / domain 300 / util 200 / config 150）、架构守卫（utils 300）；`util` 同时存在 200 与 300 两个上限 | 合并为单一阈值表 |
| 3 | Rule 1 与 Rule 41 表达同一约束（新增能力建新模块） | 合并入 06-agent-rules.md |
| 4 | Rule 2 / 3 / 8 / 16 分散讲依赖方向 | 合并为 02-architecture.md |
| 5 | "return 数量 ≤ 3"与守卫子句冲突：提前返回增加 return 数但不增加复杂度 | 删除该指标，只限嵌套深度 |
| 6 | "import > 15 重构依赖"是错误代理指标：导入标准库数量与耦合无关 | 删除，改为按依赖图与模块边界判断 |
| 7 | "API 必须幂等"过度泛化：POST 创建、日志写入天然不幂等 | 收窄为"可重试的写操作必须幂等" |
| 8 | "领域模型 > 数据模型"无条件成立，对 CRUD 内部工具是过度设计 | 补例外条件 |
| 9 | 测试比例 70/20/10 写成硬规则，与系统类型无关 | 改为原则性表述 |
| 10 | Refactor Pipeline 把"添加测试"排在拆分之后，重构在没有安全网时进行 | 改为先补 characterization test 再拆 |
| 11 | "所有重大变更必须生成 ADR"粒度过粗，日常改动也套用会淹没真正重要的决策 | 收窄到难以逆转的决策 |
| 12 | 缺少版本控制、评审、发布、数据迁移的流程规则，从"写代码"直接跳到"部署" | 新增 04-process.md |
| 13 | 缺少代码级规范（命名、函数、注释、错误处理、重复），只有模块与架构 | 新增 01-code-style.md |
| 14 | 圈复杂度 15 与"平均函数长度 40"混列在 Complexity Budget 中，量纲与用途不同 | 拆入统一阈值表并标注超限动作 |
| 15 | 开头 5 行受众 + 7 行目标，是 exposition 而非规则 | 压缩为索引的定位段落 |
| 16 | 规则全部包在 ```text 代码块里，信息密度低、检索困难 | 改为正文与表格 |
