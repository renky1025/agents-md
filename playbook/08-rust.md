# Rust 编程规范与最佳实践

版本：1.0
适用范围：本机所有 Rust 项目（应用、库、CLI、服务端、WASM）
依据：以《Rust 编程之道》的语言模型主线（所有权、借用、类型系统、分层错误处理、unsafe 安全抽象）为骨架，按 Rust 1.98 / edition 2024 的现状修订与补充

**与 01-07 的关系**：语言无关的规则以 01-07 为准，本文件只写 Rust 特有、或通用规则在 Rust 中的具体形态。两者冲突时，冲突点通常是通用规则说得过粗，以本文件为准，并在交付说明里指出。

---

## 0. 如何使用本规范

- **必须**：硬约束，违反需在 PR 中写明理由。
- **应当**：默认选择，偏离时需能说出具体收益。
- **禁止**：没有例外，除非有 `SAFETY` 或 `PERF` 注释论证。

一条总原则：**让编译器承担能承担的检查**。类型、所有权、`#[must_use]`、lint 都比 code review 便宜且不会遗忘。凡是能表达成类型约束的事情，不要退化成注释或运行时判断。

本规范只约束「怎么写」，不约束「写什么」。业务正确性由测试保证。

## 1. 工具链与 edition

### 1.1 版本与构建

- **必须** 在 `Cargo.toml` 显式声明 `edition`。新项目 `2024`，存量项目至少 `2021`。
- **必须** 声明 `rust-version`（MSRV），CI 用该版本单独构建一次。
- **必须** 提交 `Cargo.lock`（应用与二进制）；库 crate 可不提交，但 CI 要锁定依赖验证。
- **必须** CI 执行 `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`。
- **禁止** 使用 `extern crate`、`#[macro_use]`（2015 遗留写法）。
- **禁止** 在稳定版工具链上依赖 feature gate；必须依赖时需要 nightly 的固定日期版本，并单独记录。

```toml
[package]
name = "my-service"
version = "0.1.0"
edition = "2024"
rust-version = "1.85"
```

### 1.2 lint 配置

lint 写在 `Cargo.toml` 的 `[lints]` 段，不散落在源码里。一处可见、可审查、可对比。

```toml
[lints.rust]
unsafe_op_in_unsafe_fn = "deny"
unused_must_use = "deny"
missing_debug_implementations = "warn"
rust_2018_idioms = { level = "warn", priority = -1 }

[lints.clippy]
all = { level = "warn", priority = -1 }
pedantic = { level = "warn", priority = -1 }
todo = "deny"
dbg_macro = "deny"
unwrap_used = "warn"
expect_used = "warn"

# 库 crate 开启；二进制 crate 的 main 处按需 allow 并写明 reason
# print_stdout = "warn"
# print_stderr = "warn"

# 新项目逐步开启，初期噪音大，先观察再加
# indexing_slicing = "warn"
# arithmetic_side_effects = "warn"
# missing_errors_doc = "warn"
# missing_panics_doc = "warn"
```

规则：

- **禁止** 用 `#[allow]` 关闭 `clippy::all` 或 `clippy::pedantic` 整组，只能关单条 lint。
- **必须** 为每处豁免写明 reason：

```rust
#[allow(clippy::too_many_arguments, reason = "generated by build script")]
```

- **禁止** 提交 `dbg!`、调试用 `println!`。库代码用 `tracing` 或 `log`，二进制入口处允许打印并显式 `#[allow(clippy::print_stdout, reason = "CLI entry")]`。
- `unsafe_code` 是否全局 `deny` 由项目决定：纯业务服务建议 `deny`；涉及 FFI 或热点优化则保持 allow，但走第 11 章流程。

### 1.3 edition 2024 的强制变化

升级 edition 必须处理语义变化，不能只改字段：

| 变化 | 影响 | 处理 |
| --- | --- | --- |
| `unsafe extern` 块 | `extern "C" {}` 必须写成 `unsafe extern "C" {}` | 逐个补 |
| `unsafe_op_in_unsafe_fn` 默认 warn | `unsafe fn` 内调用 unsafe 操作需显式 `unsafe {}` | 把 unsafe 块缩到最小 |
| RPIT 生命周期捕获 | `-> impl Trait` 默认捕获全部输入生命周期 | 用 `+ use<'a, T>` 精确声明 |
| 临时值作用域调整 | `if let` 的临时值更早 drop | 需要延长时先 `let` 绑定 |
| `gen` 成为保留字 | 变量名 `gen` 报错 | 改 `rng` / `generator` |
| `static mut` 取引用 | 2021 仅警告，2024 为错误 | 改 `AtomicXxx` / `OnceLock` |

除「RPIT 生命周期捕获」与「临时值作用域调整」两项外，其余均在本机 rustc 1.98 实测确认。

## 2. 命名

### 2.1 大小写

| 元素 | 风格 | 示例 |
| --- | --- | --- |
| crate / module / 文件 | `snake_case` | `http_client` |
| type / trait / enum variant | `UpperCamelCase` | `HttpClient`, `ParseError` |
| function / method / 局部变量 | `snake_case` | `parse_header` |
| const / static | `SCREAMING_SNAKE_CASE` | `MAX_RETRIES` |
| const 泛型参数 | `UpperCamelCase` | `const N: usize` |
| lifetime | 小写短名 | `'a`, `'de` |
| macro | `snake_case!` | `vec!` |

rustfmt 不检查命名，靠 `clippy::pedantic` 的 `upper_case_acronyms` 等兜底。

### 2.2 语义

- **禁止** 缩写公开接口名：`user_count` 而非 `uc`。局部变量、闭包参数、lifetime 可用短名。
- **禁止** 类型名加 `Trait` / `Impl` 后缀，trait 名本身就是抽象。
- **必须** getter 不加 `get_`：`fn len(&self)`、`fn name(&self)`。`get_` 保留给可能失败或带索引的访问（`HashMap::get`、`slice::get`）。
- **必须** 布尔方法用 `is_` / `has_` / `can_`，且避免否定命名：`is_empty` 而非 `not_ready`。
- **必须** 转换方法遵循标准语义：`as_` 零成本借用转换，`to_` 做可能分配的转换，`into_` 消费 self。`to_` 返回 `Result` 的只能是解析类方法（如 `to_string` 除外）。
- **必须** 迭代器类型以 `Iter` / `IterMut` / `IntoIter` 结尾。
- **必须** trait 方法是「动词」，trait 名是「能力或角色」：`Read`、`Serialize`、`IntoIterator`。
- **避免** 同一 crate 内 type 与 module 同名，导入时会产生歧义。

### 2.3 语言约定

- 标识符一律英文，禁止拼音。
- 注释与文档用中文；日志键名、错误消息用英文，便于 grep 与告警规则匹配。

## 3. 格式化与模块组织

### 3.1 rustfmt

- **必须** 使用 rustfmt 默认配置；`cargo fmt --check` 不过就是缺陷。
- 项目根 `rustfmt.toml` 只允许调整以下项：

```toml
edition = "2024"
max_width = 100
```

- `imports_granularity` / `group_imports` 目前需要 nightly rustfmt。只用 stable 时删掉，改为手工遵守 3.2。
- **禁止** 手工对齐、手工折行去对抗 rustfmt。

### 3.2 导入顺序

固定三组，组间空行：标准库 -> 第三方 -> 本 crate。

```rust
use std::collections::HashMap;
use std::sync::Arc;

use serde::Deserialize;
use tokio::sync::Mutex;

use crate::config::Config;
use crate::error::Error;
```

- **禁止** 通配符导入。唯一例外：测试模块的 `use super::*;`，以及刻意设计的 prelude。
- **禁止** 在函数体内 `use`，除非避免循环依赖；缩短冗长约束应改用 `where`。

### 3.3 模块与可见性

- **必须** 采用 `lib.rs` + `main.rs` 的双入口结构：`lib.rs` 承载全部逻辑并对外导出，`main.rs` 只做参数解析与编排。二进制 crate 无法被外部调用，不抽 `lib.rs` 就写不了集成测试。
- **必须** 新代码用 `foo.rs` + `foo/` 目录，**禁止** 使用 `mod.rs`（2018 之前的写法，与同名文件难以区分）。
- **必须** 可见性最小化：默认私有 -> `pub(crate)` -> `pub(in path)` -> `pub`。注意 `pub(super)` 等价于 `pub(in super)`。
- **必须** 结构体字段逐个标注可见性；enum 变体没有独立可见性，随枚举走。
- **必须** 公开 API 在 crate 根用 `pub use` 重导出，用户不必关心内部路径。
- **禁止** `pub` 你不打算承诺语义的字段；用构造函数加访问器。
- **必须** 路径显式化：`crate::`、`super::`、`self::`。2018 起 `pub(in ...)` 内的路径必须以 `crate` 开头。

```
src/
  lib.rs           # 声明 mod + pub use 重导出，无逻辑
  main.rs          # 参数解析 + 调用 lib
  error.rs         # 统一错误类型
  http/
    mod.rs         # 仅声明与重导出
    client.rs
    request.rs
```

- **必须** 单文件超 500 行视为拆分信号（不是硬门槛，但超出要能说明）。
- **必须** 模块文件开头一行说明职责；每个 `pub` 项写文档注释。

### 3.4 Cargo 与依赖

- **必须** 测试、基准、示例依赖放 `[dev-dependencies]`，不进生产依赖图。
- **必须** 多 crate 用 `[workspace]`，共享 `target/` 与唯一 `Cargo.lock`。
- **必须** 可选功能走 `[features]` + `#[cfg(feature = "...")]`，默认 feature 集保持最小。
- **禁止** 通配版本号 `*`；使用 SemVer 约束。`path` 依赖仅限本地，含 path 依赖的包无法发布。
- **必须** `[package]` 补全 `description`、`license`、`repository`，否则 `cargo publish` 失败。
- **必须** 新增依赖需说明理由；CI 跑 `cargo audit`（漏洞）与 `cargo deny`（许可证、重复依赖）。
- crate 名用连字符，代码中自动转下划线；不要用 `-rs` / `_rs` 后缀，Cargo 会剥离。
- Token、密钥走环境变量或本机配置，**禁止** 进仓库、进日志。

## 4. 表达式与流程控制

Rust 的语法地基是「一切皆表达式」。理解**位置表达式**（place expression：有稳定内存位置、可赋值、可借用）与**值表达式**（value expression：临时值）的区分，就能统一理解 `let`、`match`、`&`、移动语义的行为。

- **必须** 区分：对位置表达式取 `&` 得到借用；把位置表达式放进值上下文会发生 move（`Copy` 类型则是复制）。
- **必须** 用 `loop` 而非 `while true` 表达无限循环。`loop` 的类型是 `!`，编译器能据此推断控制流永不正常返回；`while true` 的循环体被视为返回 `()`，在需要返回值的函数里会造成类型不匹配。
- **必须** `match` 穷尽所有分支；确实不需要的分支用 `_` 并写注释说明为什么不可能出现。
- **必须** 单分支匹配用 `if let`；「匹配失败就提前返回」用 `let-else`：

```rust
let Some(value) = map.get(&key) else {
    return Err(Error::MissingKey(key.clone()));
};
```

- **必须** 用 guard clause 拍平嵌套，嵌套不超过 3 层。
- **必须** 用 `?` 而不是手写 `match` 只为了原样返回错误。
- **禁止** 用 panic 做控制流；`unreachable!()` 只用于逻辑上确实不可达的分支，并在注释里说明不变量。
- **应当** 用迭代器代替显式下标循环（见第 7 章）。
- 单个函数不超过 80 行；超过则拆子函数。

## 5. 类型系统与 API 设计

### 5.1 用类型表达约束

- **必须** 用 enum 表达互斥状态，而不是 `bool` 组合或字符串标签：

```rust
// 禁止
struct Connection { is_connected: bool, is_authenticated: bool, is_closed: bool }

// 正确
enum Connection {
    Disconnected,
    Authenticated { token: Token },
    Closed { reason: String },
}
```

- **必须** 用 newtype 给裸类型加语义和不变量。`type` 别名只改名字、不改行为，**禁止** 用它冒充新类型：

```rust
pub struct UserId(u64);
pub struct OrderId(u64);

fn transfer(user: UserId, order: OrderId) {}  // 编译期挡住参数颠倒
```

- **必须** 非法状态应当无法构造（typestate / RAII），而不是构造后再校验。状态转换用「消费 self、返回新状态」的方法：

```rust
impl Connection {
    fn authenticate(self, token: Token) -> Result<Self, Error> { /* ... */ }
}
```

- **必须** 多个返回值语义重要时用具名 struct，而不是长元组。
- **禁止** 用 `Option<Option<T>>` 表达三种状态，用 enum。
- **必须** 为公开类型实现 `Debug`（`missing_debug_implementations` 已开）；同时含敏感字段时实现手写 `Debug` 做脱敏。

### 5.2 trait 设计

- **必须** trait 小而聚焦，一个 trait 一组行为。
- **必须** 需要异构集合或向下转型时用 `dyn Trait`；否则用泛型或 `impl Trait`（静态分发、无虚表）。
- **必须** 想让外部 crate 无法实现你的 trait 时用 sealed trait：

```rust
mod sealed { pub trait Sealed {} }

pub trait MyTrait: sealed::Sealed {
    fn do_thing(&self);
}
```

- **必须** trait 对象必须满足对象安全：方法不能是泛型、必须有接收者、`Self` 不能出现在参数或返回位置、无关联常量。个别方法可用 `where Self: Sized` 排除出虚表。
- **必须** 只实现 `From<A> for B`，`Into` 由标准库 blanket impl 自动获得。**禁止** 同时手写 `From` 与 `Into`。
- **禁止** 用 `Deref` 做「继承式复用」，`Deref` 只用于智能指针语义。业务类型用组合 + 显式转发方法。
- **必须** 注意孤儿规则：`impl` 的 trait 与类型至少一个是本 crate 的。`Option<LocalType>` 仍算外部类型（外层是 `Option`），`Box<LocalType>` 因 `#[fundamental]` 例外。
- **必须** 明确区分 `Display`（面向用户输出）与 `Debug`（面向诊断），不要混用。

### 5.3 类型转换

- **禁止** 用 `as` 做可能丢失信息的数值转换，`as` 会静默截断。
- **必须** 可能失败的转换用 `TryFrom` / `TryInto`：

```rust
let n: u8 = u8::try_from(big_number).map_err(|_| Error::Overflow)?;
```

- **必须** 无损转换用 `From` / `Into`；API 入参需要接受多种形态时用 `impl Into<String>` / `impl AsRef<Path>`。
- **必须** trait 方法同名产生歧义时用完全限定语法 `<S as A>::test()`，而不是 `A::test()`。

### 5.4 泛型与 `impl Trait`

- **必须** 多个约束用 `where` 子句，避免签名不可读。
- **必须** 知道参数位置的 `impl Trait` 等价于匿名泛型；两个 `impl Trait` 参数是不同类型，不能互相运算。需要「同一类型」时改回具名泛型。
- **必须** 返回位置的 `impl Trait` 是静多态，注意 edition 2024 默认捕获全部输入生命周期；只在需要时用 `+ use<'a, T>` 收窄。
- **应当** 公开库 API 用泛型；内部巨型函数可考虑 `dyn` 以减少单态化带来的代码膨胀。

### 5.5 `Copy` 与相等性

- **必须** `Copy` 只在所有字段都 `Copy` 时 `derive`，且 `Copy` 要求 `Clone` 同时存在。
- **禁止** 含 `String` / `Vec` / `Box` / 任何堆所有权的类型实现 `Copy`。
- **必须** 实现 `Hash` 的类型同时实现 `Eq`；只实现 `PartialEq` 的类型（含浮点）不能作 `HashMap` 键。
- **必须** 实现 `Ord` 前确认字段构成全序；浮点只能用 `PartialOrd` 或 `ordered-float`。

## 6. 所有权与借用

### 6.1 三条借用规则

规范里反复引用的一句话：**共享不可变，可变不共享**。

1. 借用的生命周期不长于出借方；
2. 存在可变借用时不能有任何其他借用（含不可变借用）；
3. 不可变借用不能再出借为可变借用。

这三条等价于读写锁的语义，也是 `Send`/`Sync` 与并发安全的基础。

### 6.2 参数传递

| 场景 | 写法 |
| --- | --- |
| 只读字符串 | `&str` |
| 只读切片 | `&[T]` |
| 只读字节流 / 任意可转字符 | `impl AsRef<str>` / `impl AsRef<[u8]>` |
| 只读路径 | `impl AsRef<Path>` |
| 需要拥有所有权（存储、跨线程） | `T` 或 `impl Into<T>` |
| 需要原地修改 | `&mut T` |
| 小 `Copy` 类型（`u32`、enums） | 按值 |

规则：

- **禁止** 使用 `&String`、`&Vec<T>`、`&Box<T>` 作为参数类型。用 `&str`、`&[T]`、`&T`，调用方零成本传入。
- **禁止** 使用 `[T]` 或 `str` 作为参数类型（DST，必须经引用或 `Box`）。
- **必须** 结构体字段存拥有所有权的类型（`String`、`Vec<T>`、`PathBuf`），不要存 `&str`，除非类型本身就是零拷贝视图（`Message<'a>` 这类解析结果）。
- **必须** 需要返回修改结果时优先 `&mut` 原地修改，而不是「传入容器、返回新容器」。

### 6.3 clone 策略

- **禁止** 用 `clone()` 消除借用检查器报错，除非能说明该数据确实是独立副本。
- 解除借用冲突的顺序：缩小借用作用域 -> 调整 `let` 顺序 / 提前 `drop` -> 用索引或 `split_at_mut` 拆分 -> 最后才 clone。
- **必须** 审视热路径上的 clone：循环内 clone = 分配 + 拷贝。
- `Rc::clone` / `Arc::clone` 只加计数，但原子计数仍有开销，不是零成本。

```rust
// 两个可变借用冲突时，用 split_at_mut 拆出不相交的两段
let (left, right) = slice.split_at_mut(mid);
```

### 6.4 生命周期

- **必须** 依赖省略规则，不写冗余标注：

```rust
// 冗余
fn first<'a>(s: &'a str) -> &'a str
// 正确
fn first(s: &str) -> &str
```

- **必须** 只在多个输入引用、返回引用可能来自其中之一时显式标注。
- **必须** 无输入引用却要返回引用是不可能的，改为返回拥有所有权的类型。
- **避免** 给业务结构体加生命周期参数；这会传染整个类型。优先拥有数据，只对解析视图、零拷贝 API 引入生命周期。
- **必须** trait 对象持有非 `'static` 借用时写 `Box<dyn Trait + 'a>`，不要依赖默认 `'static`。
- 标注不会延长寿命，只告诉借用检查器事实。

### 6.5 智能指针选型

| 需求 | 选择 | 说明 |
| --- | --- | --- |
| 堆分配、递归类型 | `Box<T>` | 唯一所有权，稳定地址 |
| 单线程共享只读 | `Rc<T>` | 非原子计数 |
| 跨线程共享只读 | `Arc<T>` | 原子计数 |
| 打破循环引用 | `Weak<T>` | 父/子、双向链表 |
| 单线程共享可变 | `Rc<RefCell<T>>` | 运行时借用检查 |
| 小 `Copy` 字段的内部可变 | `Cell<T>` | 无运行时检查、永不 panic |
| 跨线程互斥 | `Arc<Mutex<T>>` / `Arc<RwLock<T>>` | 见第 9 章 |
| 写时复制 | `Cow<'a, T>` | 读多写少、统一 `&str` 与 `String` |
| 全局只读初始化 | `OnceLock<T>` / `LazyLock<T>` | std 内置，替代 `lazy_static` |

规则：

- **禁止** 把 `Rc<RefCell<T>>` 当默认结构；它是借用检查失败后的兜底，不是设计目标。
- **必须** 明白 `Rc` 不是 `Send`、`RefCell` 不是 `Sync`；跨线程必须 `Arc` / `Mutex`。
- **必须** 对 `RefCell::borrow_mut` 的作用域保持最短；同时两个 `borrow_mut` 是运行时 panic，不是编译错误。
- **必须** 用 `Weak` 打断循环引用。Rust 保证内存安全，但**不保证不泄漏**：引用计数环、`mem::forget`、`Box::leak` 都会泄漏。
- **必须** 默认栈分配，能放栈上就不要放堆上；`Box` 用于递归类型、大对象移动、trait object。
- **禁止** 用 `mem::forget` 做常规资源释放；FFI 移交所有权时用 `ManuallyDrop` 表达意图更清楚。

### 6.6 借用检查摩擦的处理

| 症状 | 修法 |
| --- | --- |
| 同时需要两个 `&mut` | `split_at_mut`、`chunks_mut`，或改为索引访问 |
| 循环里修改同时遍历的集合 | 先收集要改的键，循环外统一改 |
| 返回局部变量引用 | 返回拥有所有权的类型 |
| 结构体自引用 | 用索引 + `Arena`，或 `Pin` + 初始化后不再移动 |
| 跨 `.await` 持有借用 | 缩短作用域、clone 所有权，或改用 `Arc` |
| 确实需要共享可变 | 退到 `RefCell` / `Mutex`，并在注释说明为什么借用检查无法表达 |

**禁止** 遇到借用报错就先上 `Cell`/`RefCell`/`clone`。先判断数据是否真的需要共享可变；多数情况下是设计问题。

## 7. 函数、闭包与迭代器

### 7.1 函数

- Rust 没有默认参数、没有重载。用 builder 或具名构造解决可选参数。
- **必须** 接收者选择：只读 `&self`，修改 `&mut self`，消费并转换 `self`。
- **必须** 返回 `impl Trait` 隐藏具体类型；返回裸类型时确保它是公开契约。
- **必须** 用参数模式匹配简化解构（`fn f((a, b): (u8, u8))`）。
- **必须** 发散函数（一定 panic 或无限循环）返回 `!`。
- **必须** 对外暴露的错误类型、参数类型写完整类型标注，不依赖复杂推导。
- 泛型推断不足时用 turbofish 显式标注：`"42".parse::<i32>()`。

### 7.2 闭包

闭包按捕获方式实现为 `Fn` / `FnMut` / `FnOnce` 三者之一，继承关系 `Fn: FnMut: FnOnce`：

| 捕获行为 | 实现 trait |
| --- | --- |
| 只读捕获 | `Fn` |
| 需要修改捕获的环境 | `FnMut` |
| 消费捕获的变量（move 掉非 `Copy` 值） | `FnOnce` |

规则：

- **必须** 参数位置的闭包用 `impl Fn(..) -> ..` 泛型（静态分发、可内联）。
- **必须** 需要存储、放入异构集合、跨 FFI 传递时用 `Box<dyn Fn(..) -> ..>`。
- **必须** 返回闭包时用 `impl Fn(..) -> ..`；闭包逃逸出当前栈帧时**必须** `move`，否则返回悬垂引用。
- **必须** 跨线程传递的闭包同时满足 `Send + Sync + 'static`。
- **禁止** 用 `fn` 指针试图捕获环境；需要捕获就用闭包。
- **禁止** 为单个闭包手写 struct 并实现 `Fn`（需 nightly，且没有必要）。
- 需要注意：edition 2021 起闭包按字段做 disjoint capture，可能捕获比预期更细，也会影响 `Drop` 时机。

### 7.3 迭代器

**必须** 默认用迭代器链式写法，避免下标循环：

```rust
// 禁止
let mut out = Vec::new();
for i in 0..items.len() {
    if items[i].active { out.push(items[i].id); }
}

// 正确
let out: Vec<_> = items.iter().filter(|i| i.active).map(|i| i.id).collect();
```

- **必须** 适配器链以消费器收尾（`collect` / `sum` / `fold` / `for_each` / `count`）。适配器是惰性的，不消费就不执行。
- **必须** 需要 `break` 或提前返回时才用 `for` 循环。
- **必须** 已知长度时预分配：`Vec::with_capacity(iter.size_hint().0)`。
- **必须** 自定义迭代器同时实现 `size_hint`；可能时实现 `DoubleEndedIterator`、`ExactSizeIterator`。
- **必须** 为第三方迭代器加扩展方法时用 extension trait，而不是自由函数：

```rust
trait IterExt: Iterator {
    fn step(self, n: usize) -> Step<Self> where Self: Sized;
}

impl<I: Iterator> IterExt for I {}
```

- **禁止** 用 `for` + `push` 代替 `map` + `collect`；**禁止** 用 `.iter().cloned().collect()` 只是为了让类型匹配时不做思考（先看是否能用 `&T` 借用）。
- 内部迭代器（`any` / `all` / `fold` / `find`）不能 `break`，需要提前退出时用 `try_fold` 或改为外部迭代。

### 7.4 常用设计模式

| 模式 | 适用 | Rust 写法要点 |
| --- | --- | --- |
| Builder | 多可选参数构造 | 每个 setter 返回 `Self`，`build()` 校验不变量；参考 `std::process::Command` |
| Typestate | 状态机、协议握手 | 每个状态一个类型，转换方法消费 `self` |
| Newtype | 语义区分、封装不变量 | 单字段 tuple struct + 手写 `Deref` 例外处理 |
| RAII 守卫 | 资源释放、锁、事务 | 在 `Drop` 中释放；不要依赖析构顺序实现业务逻辑 |
| 访问者 | 数据结构与操作解耦 | 通常由 Serde、AST 等库提供，业务代码少自己写 |
| 扩展 trait | 给外部类型加方法 | `impl<T: Bound> Ext for T` |

**禁止** 照搬面向对象的继承体系。Rust 用组合 + trait；继承式分层会导致大量 `Deref` 滥用和对象安全问题。

## 8. 错误处理

### 8.1 三分法：失败 / 错误 / 异常

| 类别 | 定义 | Rust 手段 |
| --- | --- | --- |
| 失败（failure） | 违反契约（前置/后置条件、不变量） | 类型系统 + 断言，理想情况下不可构造 |
| 错误（error） | 业务上可预期、可合理处理 | `Result<T, E>` |
| 异常（exception） | 不可恢复的逻辑 bug | `panic!` / `abort` |

再叠加「值可能不存在」：

| 情形 | 手段 |
| --- | --- |
| 查不到、可选配置、空集合取极值 | `Option<T>` |
| 可能失败且需要原因 | `Result<T, E>` |
| 不变量被破坏 | `panic!` / `assert!` |
| 灾难性、必须立即终止 | `abort()` |

规则：

- **必须** 用 `Option` 只表达「有/无」，不承载原因。调用方需要知道为什么失败时必须是 `Result`。
- **禁止** 用 `Result<T, ()>` 或 `Result<T, String>` 作为公开 API 的错误类型。
- **禁止** 用 panic 代替错误返回。库代码 panic 等于把决定权强加给调用方。
- **禁止** 把「输入格式错误」当异常；它是错误，返回 `Result`。
- **必须** 用 `#[must_use]` 标注任何「忽略即错误」的返回值；`Result` 已由标准库标注。
- **必须** 区分可重试错误（超时、限流、连接重置）与不可重试错误（参数非法、鉴权失败），并在类型或字段上体现，让重试逻辑能结构化判断。

### 8.2 库 vs 应用

- **库 crate**：定义自己的具名错误枚举，实现 `std::error::Error`，用 `thiserror` 降低样板；**禁止** 依赖 `anyhow`（会抹掉调用方需要的错误类型）。
- **应用/二进制**：内部用 `anyhow::Result` 快速传播上下文，在边界转成用户可读信息或 HTTP 状态码。

```rust
// 库
#[derive(Debug, thiserror::Error)]
pub enum ConfigError {
    #[error("failed to read config file {path}")]
    Io { path: String, #[source] source: std::io::Error },
    #[error("invalid port: {0}")]
    InvalidPort(u16),
}

// 应用
fn run() -> anyhow::Result<()> {
    let cfg = Config::load().context("load config")?;
    let client = Client::new(&cfg).context("init http client")?;
    Ok(())
}
```

- **必须** 用 `?` 传播，不手写只做透传的 `match`。
- **必须** 跨越模块边界时用 `.context()` 或 `.with_context()` 补充「在做什么」，让错误链包含操作语义。
- **必须** 保留原始错误：用 `#[source]` / `source()`，**禁止** 把它 `to_string()` 拍平。
- **必须** 错误变体携带结构化上下文数据，而不是预拼接的字符串。
- **必须** `main` 返回 `Result`：`fn main() -> anyhow::Result<()> { run() }`。
- **必须** 长签名用类型别名简化：`type ParseResult<T> = Result<T, ParseError>;`

### 8.3 unwrap / expect / panic

- **禁止** 库代码使用 `unwrap()` 与 `expect()`（`unwrap_used` / `expect_used` 已开启）。
- **允许** `expect()` 仅两类场景，且**必须**写明不变量：
  1. 编译期已证明不可能失败（硬编码正则、常量解析）；
  2. 测试代码。
- **禁止** 用 `unwrap()` 处理任何来自网络、文件、用户输入的结果。
- **必须** 断言分层：契约检查用 `debug_assert!` 系列（release 下消失）；`assert!` 只用于安全关键或开销可接受处。
- **禁止** 用 `catch_unwind` 做常规错误处理；它只用于线程隔离与 FFI 边界，并且**不能**修复已被破坏的不变量。
- **必须** 线程的 `JoinHandle` 要么 `join` 并处理 panic 传播，要么显式说明 detach；不要静默丢弃。

### 8.4 组合子

- **必须** 用组合子替代嵌套 `match`：`map`、`and_then`、`map_or`、`map_or_else`、`unwrap_or`、`unwrap_or_else`、`ok_or`、`ok_or_else`。
- **必须** 区分 `map` 与 `and_then`：返回 `Option`/`Result` 的用 `and_then`，否则会出现 `Some(Some(x))`。
- **必须** 用 `entry` API 处理「存在则更新、不存在则插入」，避免两次查找：

```rust
*counts.entry(key).or_insert(0) += 1;
```

## 9. 并发与异步

### 9.1 基础判断

- **必须** 分清并发（切分任务）与并行（同时执行）。先确认任务可切分，再谈并行。
- **必须** 分清竞态（依赖执行顺序）与数据竞争（同时读写且至少一方写）。Rust 在安全代码中消除数据竞争，但**不消除竞态**；锁能保护内存，不能保证业务顺序正确。
- **必须** 理解 `Send`（所有权可跨线程转移）与 `Sync`（不可变引用可跨线程共享）是 `unsafe` 标记 trait。`Rc` 是 `!Send`，`Cell`/`RefCell` 是 `!Sync`。
- **禁止** 手写 `unsafe impl Send/Sync`，除非走第 11 章流程并写明论证。

### 9.2 同步原语选型

| 需求 | 选择 |
| --- | --- |
| 一般共享可变状态 | `Mutex<T>` |
| 读多写少 | `RwLock<T>` |
| 计数器、标志位 | `Atomic*` |
| 移交所有权、流水线 | channel（`mpsc` / `crossbeam`） |
| 阶段会合 | `Barrier` |
| 等待谓词成立 | `Condvar` + `Mutex` |
| 子线程借用父线程栈数据 | `std::thread::scope` |

规则：

- **必须** 优先消息传递。「不要通过共享内存来通信，而要通过通信来共享内存」——所有权转移天然避免锁。
- **必须** 锁的作用域尽量短，**禁止** 持锁做 I/O、长计算或 `.await`。
- **必须** 固定全局加锁顺序并写入文档，防止死锁。必须嵌套时用 `try_lock` 并定义失败策略。
- **禁止** 在同一作用域同时持有 `RwLock` 的读锁与写锁。
- **必须** 显式处理 `Mutex` 中毒（poison）：要么 `unwrap()` 并接受 panic 传播，要么用 `PoisonError::into_inner` 恢复，并确认数据结构不变式仍成立。
- **禁止** 用 `sleep` 做同步；用 channel、`Condvar`、`park`/`park_timeout`。
- **必须** 使用有界通道提供背压；无界通道要有明确的容量假设，否则内存会无上限增长。
- **必须** `rx.iter()` 只有在所有 `Sender` 被 drop 后才结束；共享通道要逐个 `drop(tx)`。

### 9.3 原子与内存序

- **必须** 默认 `Ordering::SeqCst`；能用「发布/获取」语义时成对使用 `Release` / `Acquire`。
- **必须** `Relaxed` 只用于互不依赖的计数与统计，并写注释说明为什么不需要同步。
- **禁止** 在内存序上随机试错；每个非 `SeqCst` 的选择都要能说明它保证了什么。
- **必须** 原子变量共享时同样需要 `Arc<Atomic*>`；原子性不传递可变性。

### 9.4 异步

- **必须** 一个项目只用一个 async runtime（通常 `tokio`）；库 crate 不要硬绑定 runtime，用 feature 门控或 trait 抽象。
- **禁止** 在 async 上下文调用阻塞 API：`std::thread::sleep`、同步文件 I/O、`reqwest::blocking`、CPU 密集长循环。用 `spawn_blocking` 或 runtime 的异步版本。
- **禁止** 跨 `.await` 持有 `std::sync::MutexGuard`（不是 `Send`，且可能死锁）。改为缩小作用域或用 `tokio::sync::Mutex`。
- **必须** future 是惰性的：构造不会执行，必须 `.await` 或交给 executor。
- **必须** 给所有外部调用设置超时（`tokio::time::timeout`），并明确取消语义：drop 一个 future 即取消，被取消的分支可能留下部分状态。
- **必须** 理解 `Pin` 的契约：自引用结构移动后失效，`Pin` 是编译器接受你不移动它的承诺。手写 `unsafe { Pin::new_unchecked }` 必须给出论证。
- **必须** 自定义 `Future` 时保存并正确调用 `Waker`，`poll` 必须快速非阻塞。

```rust
// 禁止：跨 await 持锁
let guard = mutex.lock().unwrap();
do_io().await;

// 正确：用完即释放
{
    let mut guard = mutex.lock().unwrap();
    guard.update();
}
do_io().await;
```

### 9.5 并行

- **必须** CPU 密集型集合处理优先 `rayon`（`par_iter`），不要手写线程池。
- **必须** 保证并行闭包无共享可变状态；有共享状态时用 `reduce` 或先 `map` 后合并。
- **必须** 不要在 `rayon` 任务里做阻塞 I/O。
- `join` 不保证两个分支并行执行（线程池忙时会顺序执行），不要依赖它做同步。

## 10. 字符串、集合与内存

### 10.1 字符串类型选型

| 类型 | 用途 |
| --- | --- |
| `&str` | 只读借用，函数参数默认 |
| `String` | 拥有所有权、可增长、可修改 |
| `Box<str>` | 拥有所有权且不需要扩容（省一个容量字段） |
| `Cow<'a, str>` | 多数借用、少数需要拥有 |
| `OsString` / `&OsStr` | 路径、环境变量（可非 UTF-8） |
| `CString` / `CStr` | FFI 边界 |
| `Vec<u8>` | 二进制数据，不是文本 |
| `Rc<str>` / `Arc<str>` | 共享不可变字符串 |

规则：

- **必须** 记住 `String` 是 UTF-8 字节序列，`s[i]` 不存在；`len()` 是字节数不是字符数。
- **禁止** 用下标做字符定位。按字符遍历用 `chars()`，需要下标时用 `char_indices()`，按字节处理用 `as_bytes()`。
- **必须** 字符串切片前保证落在 char boundary：读用 `get()` / `get_mut()`（返回 `Option`），写前用 `is_char_boundary()` 校验。`[]`、`split_at`、`truncate` 在非边界处 panic。
- **必须** 按显示宽度对齐或截断时用 `unicode-width`；统计「用户可见字符」需要 grapheme 处理（`unicode-segmentation`），`chars().count()` 不等于视觉字符数。
- **必须** 拼接多个片段时用 `String::with_capacity` + `push_str` 或 `format!`；**禁止** 在循环里 `s = s + &t`（每次重新分配）。
- **禁止** 用 `to_ascii_uppercase` 等 ASCII 专用方法处理可能含非 ASCII 的文本。
- **必须** 路径用 `Path` / `PathBuf`，OS 参数用 `OsStr` / `OsString`；不要把路径塞进 `String` 再转回去。

### 10.2 集合选型

| 需求 | 选择 |
| --- | --- |
| 顺序追加、按下标访问、栈 | `Vec<T>` |
| 两端进出、队列 | `VecDeque<T>` |
| 无序键查找 | `HashMap<K, V>` |
| 有序遍历、范围查询 | `BTreeMap<K, V>` |
| 去重与集合运算 | `HashSet` / `BTreeSet` |
| 优先队列（最大堆） | `BinaryHeap<T>` |
| 保持插入顺序 | `indexmap::IndexMap`（第三方） |
| 元素很少（< 10） | `Vec` + 线性查找往往更快 |

规则：

- **禁止** 用 `LinkedList`。它的 O(1) 中间插入在实践中几乎不需要，而缓存局部性、分配开销全面劣于 `Vec`。
- **必须** 已知规模时预分配：`Vec::with_capacity(n)`、`HashMap::with_capacity(n)`。
- **必须** 知道 `clear()` / `truncate()` 不释放容量；需要归还内存时用 `shrink_to_fit`。
- **必须** `reserve(n)` 保证的是「至少还能再放 n 个」，不是总容量设为 n。
- **必须** 用 `entry` API 做计数与分组，避免 get-then-insert 两次查找。
- **必须** 合并两个 map 用 `extend`，不要 `for` 循环逐条 `insert`。
- **必须** 不需要稳定顺序时用 `sort_unstable`（省内存、更快）；`binary_search` 前必须已排序。
- **必须** `HashMap` 的键类型实现 `Eq + Hash`；浮点键用 `ordered-float` 或转成整数分位。
- **必须** 面向外部输入的 `HashMap` 保持默认 `SipHash`（抗哈希碰撞 DoS）；只有内部可信数据才考虑换 `ahash` / `fxhash`，并说明收益。

### 10.3 内存与布局

- **必须** 用 `std::mem::size_of` 检查高频分配类型的尺寸；大结构体按值传参会复制。
- **必须** 枚举含大变体时装箱，避免整个枚举被最大变体撑大：

```rust
enum Node {
    Small(u64),
    Large(Box<LargeData>),   // 而不是内联 LargeData
}
```

- **必须** `#[repr(C)]` 只用于 FFI 或布局敏感场景；普通结构体字段顺序由编译器优化。
- **必须** 分清「定义位置」与「实例存储位置」：结构体定义不决定放栈还是堆，取决于实例如何使用、被谁拥有。

## 11. unsafe 使用规范

### 11.1 定位

`unsafe` 不是性能开关，是「编译器无法证明、由你承担证明责任」的契约标记。它只放开五种操作：

1. 解引用裸指针；
2. 调用 `unsafe` 函数；
3. 访问或修改可变静态变量；
4. 实现 `unsafe trait`；
5. 读写 `union` 字段。

除此之外所有规则照旧生效。

### 11.2 必须遵守

- **必须** 在 crate 根声明策略：

```rust
#![deny(unsafe_code)]    // 默认：完全禁止
// 或
#![warn(unsafe_code)]    // 允许，但每处需审查
```

- **必须** 把 unsafe 封装在安全抽象之后；`pub` API 不允许把 unsafe 前置条件转嫁给调用方却不在文档里写明。
- **必须** 让 `unsafe` 块尽可能小，只包住真正需要的操作。
- **必须** 每个 `unsafe` 块写 `SAFETY:` 注释，说明指针来源、对齐、初始化、别名、生命周期与线程安全依据：

```rust
// SAFETY: `ptr` 来自 `Vec::as_mut_ptr`，且 `index < self.len`，
// 指针有效、对齐、可写，且与任何其他引用不重叠。
unsafe { *self.ptr.add(index) = value; }
```

- **必须** 安全函数的内部 unsafe 在文档里用 `# Safety` 段落写明调用者义务（如果函数本身是 unsafe 的）。
- **必须** 在 `unsafe fn` 内显式写 `unsafe {}` 块，不依赖函数级上下文（edition 2024 默认要求）。

### 11.3 必须验证的内容

| 类别 | 检查点 |
| --- | --- |
| 指针 | 非空、对齐、有效、生命周期内未释放、无别名冲突 |
| 长度 | 索引 `< len`、乘法不溢出、容量足够 |
| 初始化 | `MaybeUninit` 使用前已写入，且不重复 drop |
| 类型转换 | `transmute` 两端大小相同、布局兼容、不破坏 niche 布局 |
| 型变 | 内部可变性类型不能协变，用 `PhantomData<fn(T)>` 表达不变 |
| dropck | 拥有关系用 `PhantomData<T>` 表达，避免过早释放 |
| FFI | panic 不跨边界、字符串以 `\0` 结尾、ABI 与结构体布局匹配 |

规则：

- **禁止** `transmute` 用于能写成 `as` / `From` / `to_bits` 的转换；能不用就不用。
- **禁止** 让 panic 逃逸 FFI 边界；在边界用 `catch_unwind` 转换错误码，且不得掩盖已破坏的不变量。
- **必须** 用 `NonNull<T>` 表达非空指针，`Option<NonNull<T>>` 表达可空。
- **必须** 含 `Drop` 的类型不得移出字段；需要转移用 `ManuallyDrop`。
- **必须** 完成所有可能 panic 的操作后再提交长度、容量等不变量（panic safety）。
- **必须** 对 unsafe 代码跑 Miri（`cargo +nightly miri test`），并发代码加 `loom`，FFI 与内存问题加 ASan/UBSan。
- **必须** 混合代码（C/Rust 交界）遵守三条：所有权归属明确、生命周期不越界、错误不穿透边界。

### 11.4 何时允许使用

只有以下情况，且需在 PR 中说明并给出验证方式：

1. FFI 调用外部库或对外暴露 ABI；
2. 实现安全抽象所必需（自研容器、无锁结构、自定义分配器）；
3. 经 benchmark 证明是瓶颈，且安全版本无法达标。

**必须** 同时写清：触发条件、不变量、失效后的后果、测试覆盖方式。

## 12. 宏

- **必须** 优先用函数、泛型、trait、`const fn`；宏是最后手段。
- **必须** 按用途选类型：
  - 语法模式、可变参数、重复结构 -> `macro_rules!`；
  - 派生、属性、需要读取类型结构的代码生成 -> 过程宏。
- **必须** 导出声明宏时用 `$crate::` 引用本 crate 项，不依赖调用方作用域；内部规则用 `@internal` 前缀；处理尾逗号。
- **必须** 过程宏使用独立的 `proc-macro` crate，基于 `syn` + `quote`，保留泛型参数与 `where` 子句，生成代码用全限定路径避免名字冲突。
- **必须** 过程宏的错误用 `syn::Error::to_compile_error` 指向调用点的 span，让报错落在用户代码上。
- **禁止** 依赖 `TypeId` 或类型名做运行时分发作为公共契约；类型名不是稳定 ABI。
- **必须** 宏展开后的代码可读：用 `cargo expand` 检查；必要时把逻辑放进普通函数，宏只做胶水。

## 13. 测试与文档

### 13.1 测试

- **必须** 单元测试放在被测模块的 `#[cfg(test)] mod tests`；集成测试放 `tests/`。
- **必须** 公开 API 有测试；`Err` 分支与边界值必须有测试，不能只测 happy path。
- **必须** 断言失败时给出可定位的信息，用 `assert_eq!` 而非 `assert!`，消息里带实际值。
- **必须** `#[should_panic(expected = "...")]` 写明确切消息，避免匹配到无关 panic。
- **应当** 用 `let Err(e) = f() else { panic!("expected error") };` 取错误，不要 `is_err()` 之后再猜原因。
- **禁止** 测试之间共享可变全局状态；每个测试自建 fixture。
- **应当** 解析器、序列化、状态机引入属性测试（`proptest`），覆盖区间远大于手写用例。
- **必须** 性能敏感代码有 `criterion` 基线，性能优化必须有前后对比数据。
- **必须** unsafe 代码有针对性测试，并接入 Miri。

### 13.2 文档

- **必须** 每个模块文件开头一行说明职责；模块级文档用 `//!`，条目文档用 `///`。
- **必须** 每个 `pub` 类型、函数、trait 有文档注释：做什么、参数含义、错误条件、panic 条件。
- **必须** 库的 crate 根文档包含可运行示例（doc test 同时是测试）。
- **必须** 示例标 `no_run` / `ignore` 时说明原因。
- **禁止** 注释与代码不一致。过时注释比没有注释更危险；改代码时同步改注释，删不掉的注释就删掉。
- **必须** 错误消息、日志键名用英文；面向用户的文案用中文。

```rust
/// 解析 ISO 8601 日期字符串。
///
/// # Errors
/// 字符串格式非法或日期不存在时返回 [`ParseError`]。
///
/// # Examples
/// ```
/// let d = parse_date("2026-11-04")?;
/// assert_eq!(d.year, 2026);
/// # Ok::<(), ParseError>(())
/// ```
pub fn parse_date(input: &str) -> Result<Date, ParseError> { /* ... */ }
```

## 14. 性能

- **必须** 先测量再优化。`cargo bench`、`cargo flamegraph`、`perf` 至少用一个拿到数据。
- **禁止** 在无 benchmark 的情况下声称「优化了性能」。
- **必须** 区分「测得提升」与「预期提升」，在 PR 里如实写。
- 按顺序检查低成本收益：
  1. 循环内分配（`to_string`、`format!`、`clone`）-> 移出循环；
  2. 集合重复扩容 -> `with_capacity` / `reserve`；
  3. 不必要的 `Box` / `dyn` -> 泛型化；
  4. 大结构体按值传参 -> 传引用；
  5. 字符串拼接 -> `push_str` / `write!`；
  6. 频繁小分配 -> 对象池、`SmallVec`、`Arena`（需 benchmark 证明）。
- **必须** 优化后重新跑一遍正确性测试；unsafe 优化必须配 Miri。

## 15. 安全通用约束

- **禁止** 在代码、注释、日志中硬编码密钥、Token、密码。
- **必须** 外部输入在边界处验证一次，转换成类型后向内传递；内部不重复校验。
- **禁止** 用 `unwrap` 处理任何来自网络的解析结果。
- **必须** 对输出到终端的用户输入做转义，防止 ANSI 转义序列注入。
- **必须** 路径拼接用 `Path::join`，不要字符串拼接；不可信路径要做规范化与越界检查。
- **必须** 依赖审计进 CI：`cargo audit`、`cargo deny`。
- **必须** 序列化不可信数据时显式限制深度与大小，防止栈溢出与内存放大。

## 16. 评审清单

提交前自查：

1. `cargo fmt --check`、`cargo clippy -- -D warnings` 是否通过。
2. 是否新增 `unwrap` / `expect` / `panic!`？库代码出现即打回。
3. 错误类型是否携带上下文；`?` 传播时是否补了 `.context()`。
4. 有没有 `&String` / `&Vec<T>` 参数（应为 `&str` / `&[T]`）。
5. 循环或热路径内是否有 clone 或分配。
6. 集合是否预分配；是否该用 `entry` API。
7. 互斥状态是否用 enum 表达；是否可用 newtype 防参数串位。
8. 新增 `unsafe` 是否有 `SAFETY:` 注释、`# Safety` 文档、Miri 通过。
9. 并发：锁是否跨 `.await` 持有；共享状态是否真的需要锁；加锁顺序是否一致。
10. 公开 API 是否有文档注释与可编译示例。
11. 是否残留 `dbg!` / `println!`。
12. 新增依赖是否有理由；`cargo deny` 是否通过。

## 17. 与《Rust 编程之道》的差异勘误

这本书基于 Rust 2018（2019 年出版）。下列写法已过时，不要照抄：

| 书中写法 | 当前写法 |
| --- | --- |
| `extern crate serde;`、`#[macro_use]` | 直接 `use` |
| `mod.rs` 组织模块（示例为主） | `foo.rs` + `foo/` |
| 裸 trait 对象 `Box<Trait>` | `Box<dyn Trait>`（2018 警告，2021 起为错误，已实测） |
| `try!` 宏 | `?` |
| `failure` / `error-chain` | `thiserror`（库）+ `anyhow`（应用） |
| `Error::description()` / `cause()` | `Display` 与 `source()` |
| `lazy_static!` | `OnceLock` / `LazyLock` |
| `mem::uninitialized` | `MaybeUninit` |
| `trim_left` / `trim_right` | `trim_start` / `trim_end` |
| `AsciiExt` | 类型的固有方法 |
| `structopt` | `clap` 的 derive（`clap::Parser`） |
| `await!` 宏、`futures-preview`、`LocalWaker` | `async` / `await` + `Waker` |
| `Box::pinned` / `Pin::get_mut_unchecked` | `Box::pin` / `Pin::get_unchecked_mut` |
| `#[feature(test)]` + `#[bench]` | `criterion` |
| `.cargo/config` | `.cargo/config.toml`（或 `config`） |
| `#[rustfmt_skip]` | `#[rustfmt::skip]` |
| Crossbeam scoped thread | `std::thread::scope` |
| `stdsimd` | `core::arch` |
| 默认 jemalloc | 默认 `System`，jemalloc 需第三方 crate |
| GAT 未实现 | 已稳定，可实现 lending iterator |
| const generics 实验性 | 已稳定 |

另外两处书中表述需要修正：

- **`cargo new` 默认创建二进制 crate**，`--lib` 才创建库。书中第 10 章的说法与其后文自相矛盾。
- **`while true` 与 `loop` 的差异**主要是类型与控制流分析（`loop` 的类型为 `!`），不要沿用「`while true` 一定会类型报错」的旧解释。
- **术语更正**：书中把 `RwLock` 的中毒称为「死锁」，二者不同。poison 指持锁线程 panic 后锁被标记为污染；死锁是互相等待导致永久阻塞。

以上过时项之外，书中这些内容仍然是本规范的依据，不过时：

- 位置表达式与值表达式的划分，以及由此推导出的 move 语义；
- 三条借用规则（共享不可变，可变不共享）；
- `Deref` / `From` / `Into` 的转换语义与孤儿规则；
- 内存安全五条（未定义内存、空指针、悬垂指针、缓冲区溢出、非法释放）与「内存泄漏不属于内存不安全」的切分；
- `Send` / `Sync` 与所有权的关系；
- 失败 / 错误 / 异常三分法，以及「类型系统 + 断言」消除失败；
- unsafe 安全抽象的三大原则与 `SAFETY` 论证方式。
