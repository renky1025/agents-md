# 03 测试

> 归属：AI Coding Agent 软件工程手册

- **测试是重构的前提，不是交付的装饰。** 没有测试覆盖的代码，不允许重构。
- **先写失败测试**：修 bug 先写能复现的测试；加功能先写能描述行为的测试。看到它红，再让它绿。
- **测试行为，不测实现**。断言公开行为与输出，不断言私有方法调用次数。
- **一个测试一个概念**，测试名描述场景与期望：`test_rejects_expired_token`。
- **F.I.R.S.T.**：快（Fast）、独立（Independent）、可重复（Repeatable）、自校验（Self-validating）、及时（Timely）。
- **测试代码与生产代码同一标准**。重复、晦涩、依赖执行顺序的测试会腐烂；腐烂的测试套件比没有更危险，因为它提供虚假的安全感。
- **隔离 IO**。单元测试不连数据库、不发网络请求。集成测试才用真实依赖或容器。
- **测试金字塔**：单元测试为主，集成测试覆盖边界与 IO，E2E 只覆盖关键业务链路。具体比例取决于系统类型——纯算法库可以几乎全是单元测试，多服务系统需要更多集成测试。**不要为凑覆盖率写无断言的测试。**
- **核心逻辑覆盖率 ≥ 80%**，这是下限不是目标。覆盖率不衡量断言质量。
- **重构前补 characterization test**：对将要改动的旧代码，先用测试固定它当前的行为（哪怕行为不理想），再动手。
