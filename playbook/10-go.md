## 0. 工具链

- **必须** 提交 `go.mod` 与 `go.sum`。`go.mod` 里的 `go` 指令同时是**语言版本**，它决定循环变量语义等行为，升级它属于语义变更，不是简单改版本号。
- **必须** 用 `toolchain` 指令固定构建版本，避免不同机器用不同工具链构建出不同行为。
- **必须** 提交前跑：`gofmt -l .`（应为空）、`go vet ./...`、`go test -race ./...`。
- **应当** CI 追加 `staticcheck` 或 `golangci-lint`。`go vet` 只覆盖高频错误，不做风格与死代码分析。
- **禁止** 用 `GOFLAGS=-mod=mod` 掩盖 `go.sum` 不一致；CI 用 `-mod=readonly`。

```bash
gofmt -l . && go vet ./... && go test -race ./...
```

## 1. 类型与值语义

Go 只有值传递。`slice` 是 `{ptr, len, cap}` 描述符，`map`/`chan`/函数是引用语义的句柄——「拷贝」之后仍共享底层数据。理解这一点，后面大半规则都是推论。

### 1.1 指针与接收者

- **必须** 需要修改接收者状态、或结构体较大（超过几个机器字）时用指针接收者。
- **必须** 同一类型的方法接收者风格一致，不要混用（会让方法集割裂，接口实现变得不可预测）。
- **必须** 用编译期断言锁定接口契约：

```go
var _ io.Reader = (*File)(nil)
```

- 小结构体、不可变值（`time.Time`、自定义 ID）用值接收者。

### 1.2 slice

- **必须** 用 `make([]T, 0, n)` 表达「空且需要 append」；`make([]T, n)` 是 n 个零值元素，不是容量预留。
- **必须** 记住 `append` 在容量足够时原地写入，返回值才是新 slice。两个 slice 可能共享底层数组：

```go
a := make([]int, 2, 4)
b := append(a, 3)
b[0] = 99      // 实测：a[0] 也变成 99
```

- **必须** 需要隔离时用三索引切片强制重新分配：`append(a[:2:2], 3)`（实测 `a[0]` 不受影响），或用 `slices.Clone`。
- **必须** nil slice 与空 slice 是 API 契约的一部分：JSON 需要输出 `[]` 就返回 `[]T{}`，否则 `var s []T` 输出 `null`。判空统一用 `len(s) == 0`。
- **必须** 预知大小时预分配；循环里反复 append 大对象时尤其重要。

### 1.3 map

- **必须** 写入前 `make`。nil map 可读、可 `range`、可 `delete`，但**写入直接 panic**。
- **禁止** 把 slice / map / func 用作 key（不可比较）。
- **禁止** 依赖 map 的遍历顺序，它是随机的。需要有序输出时先收集 key 再排序。
- **必须** 知道 map 元素不可寻址：`m[k].Field = x` 编译报错（实测 `cannot assign to struct field m["k"].X in map`）。需要频繁改字段时用 `map[K]*V`，或取出、修改、放回。
- **禁止** 并发读写同一个 map（会直接 fatal，不是 panic 可 recover）。读多写少用 `sync.RWMutex`；`sync.Map` 只适合 key 集合稳定的读多写少场景。

### 1.4 new 与 make

- `make` 只用于 slice / map / chan，返回初始化后的值本身。
- `new(T)` 返回清零的 `*T`，业务代码几乎用不到；用 `&T{...}` 更直接。

### 1.5 可比较性

- 字段名、类型、顺序全同且都可比较的类型才能 `==`；含 map / slice / func 的结构体不可比较。
- **禁止** 用 `reflect.DeepEqual` 做高频比较或含函数字段的比较。

### 1.6 泛型

- Go 1.18 起可用。通用容器、算法优先用泛型，而不是 `any` + 类型断言。
- 约束用 `comparable` 或自定义 interface；类型集语法 `~int | ~string` 用于底层类型匹配。
- 泛型函数保持小；类型参数推断失败时优先简化签名，而不是让调用方处处显式实例化。

## 2. 接口

### 2.1 定义位置

- **必须** 在**消费方**定义接口，不要在生产方预先抽出宽接口（`accept interfaces, return structs`）。
- **必须** 接口保持小：一个方法能吃下大多数场景，两个方法已经很具体，超过三个通常该拆。
- 标准库的 `io.Reader` / `io.Writer` / `fmt.Stringer` 是范本。

### 2.2 typed nil 陷阱

接口是 `(type, data)` 二元组，只有两者同时为 nil 时接口才等于 nil：

```go
func f() error {
    var e *MyErr
    return e        // 实测：f() != nil
}
```

- **必须** 函数返回接口类型时，失败路径返回字面量 `nil`，不要返回具体类型的 nil 指针。
- **禁止** 用反射探测接口是否为 nil 来补救，问题应在源头修。

### 2.3 断言与嵌入

- **必须** 用双返回值形式 `v, ok := x.(T)`，或用 `switch v := x.(type)` 做多分支；单值断言在类型不符时 panic。
- **必须** 用嵌入组合能力（has-a），不要用嵌入模拟继承。匿名嵌入一个 nil 接口字段再调用其方法会 panic。
- **禁止** `*interface{}`（它只接受 `*interface{}` 本身，不是「指向任意值的指针」）。

## 3. 错误处理

- **必须** 错误是值，立即处理。**禁止** `_ = f()` 丢弃错误，禁止空 `if err != nil {}`。
- **必须** 用 `%w` 包装并保留错误链；需要判断时用 `errors.Is` / `errors.As`，不要比较错误字符串。

```go
if err := load(); err != nil {
    return fmt.Errorf("load config %s: %w", path, err)
}
```

- **必须** 错误消息小写、无结尾标点、不含换行；补充的是「在做什么」，不是「失败了」。
- **必须** 自定义错误类型实现 `error`，并提供 `Unwrap()` 以便 `errors.As` 提取。
- 需要聚合多个错误时用 `errors.Join`；`fmt.Errorf` 支持多个 `%w`（1.20 起，实测两者配合 `errors.Is` 均可用）。
- **禁止** 用 panic 表达可预期的失败。panic 只用于程序不变量被破坏。
- **必须** 库代码不 `recover`，不吞异常；恢复责任在进程/协程边界。

## 4. 并发

### 4.1 goroutine 生命周期

- **必须** 每一个 `go` 都有明确的退出路径：要么自然结束，要么响应 `context` 取消。
- **禁止** 无上限地 `go`。并发度是一个显式常量或配置项，不是调度器兜底。
- **必须** 在 goroutine 入口做 panic 恢复（进程级边界），否则一个 goroutine panic 会终止整个进程。

### 4.2 channel

- **必须** 由创建者或发送方关闭；**接收方永不关闭**；只关一次。多发送方时由协调者关闭，或不关闭交给 GC。
- **必须** 记住三种行为：nil channel 读写永久阻塞；关闭后写入 panic；关闭后读取得到零值加 `false`。
- **必须** 每个阻塞点可被取消，用 `select` 带上 `<-ctx.Done()`：

```go
select {
case ch <- v:
case <-ctx.Done():
    return ctx.Err()
}
```

- **禁止** 用 `select` + `default` 轮询等待（空转烧 CPU）；`default` 只用于非阻塞尝试。
- 缓冲容量要对应一个真实上界（并发数、批量），不要当「防阻塞」用。

### 4.3 同步原语

- **必须** `wg.Add(1)` 写在 `go` 之前；`defer wg.Done()` 是 goroutine 的第一条语句。写在 goroutine 内部会导致 `Wait` 提前返回、任务静默丢失。
- **必须** 传递 `*sync.WaitGroup`，禁止拷贝（`go vet` 会报 copylocks，实测）。
- Go 1.25 起可用 `wg.Go(func(){...})`（实测），省掉 Add/Done 样板。
- **应当** 并发 + 错误传播用 `golang.org/x/sync/errgroup`：`SetLimit` 限并发，`WithContext` 在首个错误时取消其余。

```go
g, ctx := errgroup.WithContext(ctx)
g.SetLimit(8)
for _, job := range jobs {
    g.Go(func() error { return run(ctx, job) })
}
if err := g.Wait(); err != nil { return err }
```

- **必须** 有界并发用信号量，令牌在 goroutine 内 `defer` 释放，否则 panic 会永久泄漏令牌。

### 4.4 context

- **必须** `ctx` 作为第一个参数，类型 `context.Context`，命名为 `ctx`。
- **禁止** 把 `ctx` 存进结构体字段。
- **必须** 只在请求域传值；业务参数不要塞进 context。
- **必须** 进程优雅退出用 `signal.NotifyContext`。

### 4.5 循环变量

Go 1.22 起每轮迭代生成新变量，旧的 `i := i` 捕获 bug 消失（实测 `for i := range 3` 的闭包分别得到 0/1/2）。但：

- 该行为受 `go.mod` 语言版本约束，存量模块不自动生效。
- 即便 1.22 之后，`for _, v := range s` 里的 `v` 仍是副本，修改 `v` 不会影响原切片。

### 4.6 验证

- **必须** CI 开 `-race`。
- **应当** 测试里用 `go.uber.org/goleak` 断言无 goroutine 泄漏。
- **应当** 时间相关的并发测试考虑 `testing/synctest`（Go 1.25 提供，实测可用）。

## 5. defer / panic / recover

- **必须** 资源获取后立即 `defer Close()`。
- **必须** 记住参数在 `defer` 语句处求值（实测：先 defer 再改变量，打印的是旧值）；要读最终值就传闭包。
- **必须** 记住 LIFO 且函数返回时才执行；**循环内 `defer` 会累积到函数结束**，需要每轮释放时把循环体抽成独立函数。
- **禁止** 依赖修改命名返回值来实现业务逻辑；仅 `recover` 与统一错误包装是正当用途。
- **禁止** 在 defer 中 panic（会覆盖原 panic，只有最后一个能被 recover）。
- **必须** `recover()` 直接写在 deferred 函数体内；写在被调用的嵌套函数里不生效。

## 6. 性能

- **必须** 先测量。没有 profile 数据的优化一律视为猜测。
- **必须** 了解逃逸分析：返回局部变量指针、装入接口、被闭包捕获、过大对象都会导致堆分配（实测 `&Big{}` 返回即 escapes；值传入 `any` 参数同样 escapes）。查看方式：

```bash
go build -gcflags='-m -m' ./...     # 逐层说明逃逸原因
go build -gcflags='all=-m' ./...    # 连依赖一起看
go build -gcflags='-l -m' ./...     # 关闭内联再看，内联会改变结论
```

- 判断依据是「地址是否可能活过函数返回」，不是「有没有取地址」。`new(T)` 不保证在堆上，栈变量也能取地址。
- **必须** 高频字符串拼接用 `strings.Builder` 或 `bytes.Buffer`，并 `Grow` 预分配。
- **必须** 预分配 slice；热路径避免把具体类型装箱进 `any`。

### 6.1 pprof 流程

```bash
go tool pprof -http=:8080 'http://127.0.0.1:6060/debug/pprof/profile?seconds=30'
go tool pprof -http=:8080 http://127.0.0.1:6060/debug/pprof/heap
```

- CPU 用 `profile`（采样，不是精确计时）；内存看 `heap` 的 `inuse_space`，不是 `alloc_space`；goroutine 泄漏看 `goroutine?debug=2`。
- `block` / `mutex` profile 需显式开启（`SetBlockProfileRate` / `SetMutexProfileFraction`），不要在生产常开。
- **禁止** 把 pprof 端点暴露在公网或与业务端口共用；它只在内网调试构建中出现。
- **必须** 二进制与 profile 同源，否则符号对不上。

### 6.2 benchmark 纪律

```bash
go test -run '^$' -bench . -benchmem -count=5 -benchtime=2s
```

- 固定 `GOMAXPROCS`，多轮结果用 `benchstat` 比较，单次结果没有意义。
- **禁止** 带 `-race` 跑 benchmark（数倍开销且改变时序）。
- `-benchmem` 先看 `allocs/op`，再用 `-gcflags=-m` 找原因。

## 7. 工程结构

### 7.1 布局

- 包名短、小写、无下划线、无复数冗余（`user` 不叫 `users_pkg`）。
- `cmd/<binary>/main.go` 只做装配；业务代码放 `internal/`（外部无法 import）。
- **禁止** `util` / `common` / `helpers` 这类万能包；按能力命名（`retry`、`clock`、`idgen`）。
- 依赖方向单向；`internal` 包之间避免循环。

### 7.2 模块依赖

- **必须** 提交 `go.mod` 与 `go.sum`；CI 跑 `go mod tidy` 后 `git diff --exit-code`，防止声明漂移。
- **必须** 注意：引入依赖可能**抬高 `go.mod` 的 `go` 指令**，进而悄悄提升项目的语言版本与工具链要求。实测 `go get golang.org/x/sync@latest` 把 `go 1.25` 抬到 `go 1.26.0` 并触发工具链下载。依赖变更后要检查 `go` 与 `toolchain` 两行，不能默认它是无害的。
- **禁止** 删 `go.sum` 来「修」构建问题，那只是把校验和检查关掉。
- 版本选择是最小版本选择（MVS），取满足所有 `require` 的最低版本，不是最新版。升级用 `go list -m -u all` 先看，再逐个决定。
- **禁止** `go get -u ./...` 全量升级。
- v2 及以上模块必须在路径带 `/v2` 后缀并同步 `module` 行。
- 多模块本地联调用 `go.work`（一般不入库），不要堆 `replace`；`replace` 只用于临时调试并注释原因。
- 私有模块用 `GOPRIVATE`，它自动推导代理与校验和跳过规则；通配符 `*.corp.com` 不覆盖 `corp.com` 本身。
- 工具依赖（mock 生成器、lint）用 `tool` 指令管理：`go get -tool <pkg>`（实测 1.25 支持），避免版本漂移。
- 新增依赖前确认：标准库是否已有、现有依赖是否够用、维护状态与许可证。

## 8. 测试

- **必须** 表驱动测试 + `t.Run`；用例名描述场景与期望。
- **必须** 覆盖失败路径，不只 happy path。
- **必须** 修 bug 附回归测试。
- **必须** 用 `t.Cleanup` 释放资源，不用手工 `defer` 堆叠。
- **必须** 可并行的测试标 `t.Parallel()`，但先确认无共享可变状态。
- **禁止** 用 `time.Sleep` 等异步结果；用 channel 同步或 `synctest`。
- 覆盖率 `go test -cover` 是下限参考，不是目标。

## 9. 规模

与 01-code-style 一致：文件 400 行、函数 80 行（目标 40）、嵌套 3 层、参数 4 个、圈复杂度 10。
Go 特有的补充：单文件导出符号超过 20 个，检查是否承担多个职责；`internal` 包超过 15 个文件，检查边界。

## 10. 硬规则

1. `gofmt`、`go vet`、`go test -race` 必须通过。
2. 错误必须处理；包装用 `%w`，判断用 `errors.Is/As`。
3. 禁止丢弃错误、禁止空 `if err != nil {}`。
4. 禁止用 panic 表达可预期失败。
5. 每个 goroutine 有退出路径；每个阻塞点可取消。
6. `wg.Add` 在 `go` 之前。
7. channel 由发送方关闭，接收方不关。
8. 禁止并发读写裸 map。
9. 接口在消费方定义，保持小。
10. 返回接口时失败路径返回字面量 `nil`。
11. 预分配已知大小的 slice；不要依赖 map 顺序。
12. 先 benchmark 再优化。

## 附录 A：与《深入理解 Go 语言》的差异

书中内容成于 Go 1.12-1.14（2019-2020）。以下按「过时」与「书中未覆盖」两类列出。

### A1 已过时

| 书中写法 | 当前写法 |
| --- | --- |
| `interface{}` | `any`（1.18） |
| `ioutil.ReadAll` / `ioutil.WriteFile` | `io.ReadAll` / `os.WriteFile`（1.16） |
| `go func(i int) {...}(i)` 传参避免循环捕获 | 1.22 起不再需要（受 `go.mod` 版本约束） |
| `for i := 0; i < n; i++` 做计数循环 | `for i := range n`（1.22） |
| 手写 skip 列表遍历 map | `maps.Keys` + 迭代器（1.23） |
| `sort.Slice` 手写比较 | `slices.SortFunc` / `slices.Sort`（1.21） |
| `for k := range m { delete(m, k) }` | `clear(m)`（1.21） |
| `math.MaxInt64` 边界比较 | 内置 `min` / `max`（1.21） |
| `sync.Once` + 闭包样板 | `sync.OnceFunc` / `sync.OnceValue`（1.21） |
| 手写 Add/go/Done 三件套 | `sync.WaitGroup.Go`（1.25，实测） |
| `GOPATH` 模式、`GO111MODULE` | 模块模式为默认；工作区用 `go.work`（1.18） |
| 用 `replace` 解决多模块本地联调 | `go.work`；`replace` 只作临时手段 |
| 工具依赖 `go get` 装进 `GOPATH/bin` | `go get -tool` + `go.mod` 的 `tool` 指令（1.24，实测） |
| 无工具链版本约束 | `toolchain` 指令（1.21） |
| `math/rand` | 一般场景可用，新代码考虑 `math/rand/v2`（1.22） |
| 日志用 `log` 或第三方包 | 标准库 `log/slog`（1.21，实测） |

### A2 书中未覆盖（本文件已补）

- 泛型（1.18）与 `slices` / `maps` / `cmp`（1.21）。
- `context` 完全没有出现，而它是现代 Go 服务并发的骨架。
- 错误链 `%w`、`errors.Is/As`、`errors.Join`、多 `%w`。
- `errgroup`、`goleak`、`testing/synctest`。
- `any` 替代 `interface{}` 后的接口设计习惯。
- 模块依赖治理（只换不锁、`go.sum` 校验、`-mod=readonly`）。

### A3 书中表述需要修正

- 「Go 可以无限开 goroutine」是反模式，不是语言能力展示：并发度必须有上限。
- Worker 池示例用共享结构体字段传递错误，属于数据竞争，应改 channel 传递。
- 记录 goroutine ID 只是用户自定义编号，Go 从不暴露 goroutine id，也不能依赖它做生命周期管理。
- 书中 pprof 示例把调试端点暴露在可访问端口，只能用于本机或内网调试构建。
