# 06 Agent 专属规则

> 归属：AI Coding Agent 软件工程手册

这一章约束 Agent 的行为模式，不是代码本身。

## 规则

- **新增能力 = 新模块。** 禁止把能力继续塞进已经上千行的文件。找不到合适位置时，先建边界再写代码。
- **先重构再新增。** 发现文件过大、职责混杂、重复严重时，先做小步重构，让新功能有位置可放。
- **遵循现有约定优先于通用最佳实践。** 进入陌生代码库先读同目录的相邻实现并模仿它；项目约定与手册冲突时，跟随项目并在交付说明中指出冲突。
- **只做被要求的改动。** 不加未请求的配置项、抽象层、兼容分支。清理只清自己制造的孤儿代码。
- **不静默降级。** 出错就报错。禁止用默认值、空结果、吞异常把失败伪装成成功。
- **不确定就停。** 需求有歧义、改动涉及不可逆操作（删数据、改对外契约、发布）、实现方式有两种以上合理解法且代价不同时，问用户，不要自己选。
- **交付要说清验证。** 声明"完成"必须附带实际执行过的检查与输出。没跑过的测试不说跑了。
- **记录不可逆的决策。** 满足 04-process.md 中 ADR 条件时写；日常改动不写。

## 提交前清单

按顺序自检，任何一条不通过都不提交：

1. 改动范围是否只包含本次需求？有没有顺手改的无关代码？
2. 新增或修改的函数是否 ≤ 80 行、嵌套 ≤ 3、参数 ≤ 4？
3. 是否引入了重复逻辑？能否复用已有函数？
4. 错误路径是否覆盖？有没有空 catch、吞异常、静默返回默认值？
5. 是否有新的全局状态、隐藏副作用、未声明的依赖？
6. 依赖方向是否正确？domain 是否 import 了 infra 或框架？
7. 是否补了测试？失败路径是否被覆盖？
8. 公开 API 是否有文档注释？
9. 是否残留调试代码、注释掉的代码、无归属的 TODO？
10. 是否新增依赖？理由与许可证是否可接受？
11. 是否包含密钥、token、本地路径、个人数据？
12. 格式化、lint、类型检查、测试是否实际运行并通过？
